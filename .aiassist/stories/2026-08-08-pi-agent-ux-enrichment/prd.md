## 1. 问题陈述

PI agent 对话在本机 UI 会话区**只有纯文本回显**（`MessageList.jsx` 直接渲染 `{m.text}`）：
读长回复费劲（无标题/列表/表格/代码块结构）、工具调用在对话里**零呈现**（`tool_execution_*` 事件白白丢弃）、
代码块无高亮、引用本地图片路径不显示——对话"能用但不好读、不丰富"。

参考产品 pi-web（pi coding agent 的本地 Web UI，3.8k stars）证明了这套呈现对 pi agent
工作流是标配：GFM Markdown 渲染、结构化工具调用、代码可读、会话可视化。

## 2. 解决方案

会话区对话从纯文本升级为富呈现（方向 A：React DOM 渲染管线）：

- **GFM Markdown**（表格/任务列表/删除线/链接/引用/代码块）；**HTML 一律转义**（零 XSS 面，不做 raw HTML 渲染）；
- **代码高亮**：围栏语言标记为主 + 无标记自动检测兜底；浅色/暗色**双主题**跟随全局 `data-theme`；
- **Mermaid 图表**（` ```mermaid ` 围栏）+ **KaTeX 公式**（`$`/`$$`）；**暗色主题独立配色**（显式暗色方案）；
- **图片显示**：Markdown 图片语法与本地路径引用 → 渲染为图片；
- **工具调用折叠块**：`tool_execution_*` 事件 → 消息流内折叠块（默认收起：工具名+输入摘要；展开：输入/输出/耗时；**错误默认展开标红**）；
- **流式实时增量渲染**（每个 `text_delta` 直接喂渲染器，未闭合语法暂时显示字面量）；
- **历史消息统一管线**（旧纯文本消息同一渲染器，存储契约不动，工具块不落历史）。

## 3. 用户故事

1. 作为**本机用户**，我想要 agent 回复里的代码块带高亮、表格/列表有结构，以便读长回复时快速定位重点。
2. 作为**本机用户**，我想要 agent 画的结构图（Mermaid）和公式（KaTeX）直接渲染出来，以便不切工具就能理解。
3. 作为**本机用户**，我想要 agent 执行的工具调用在对话里可见可展开（默认收起、出错即见），以便知道它做了什么、哪里失败了。
4. 作为**本机用户**，我想要 agent 引用的本地图片直接显示，以便不用手动开文件。
5. 作为**本机用户**，我想要流式输出实时呈现 Markdown（边生成边渲染），以便不等到回复完成。
6. 作为**维护者**，我想要历史消息与新消息同一渲染管线，以便渲染逻辑单一维护。

## 10. 实现决策（高层，不写代码）

### 10.1 模块边界与解耦

- **渲染组件层（renderer 内新增）**：Markdown 渲染组件（GFM + 高亮 + Mermaid + KaTeX + 图片 + 转义）+ 工具折叠块组件——纯展示组件，接收既有消息/事件数据，不触碰消息存储与事件流契约（B8 硬约束）。
- **依赖选择**：react-markdown + remark-gfm + remark-math/rehype-katex（KaTeX）+ mermaid 包（按需动态加载——mermaid 体积大，懒加载避免拖慢启动）+ 高亮库（Shiki 或 highlight.js——实现时按 M2 验证定，倾向轻量）。**均纯前端、无原生依赖**（隐含假设 1 验证点）。
- **图片路径解析**：本地路径相对会话项目目录解析（与既有工具面 cwd 语义一致）；越权（出项目目录）不渲染。
- **主题**：复用既有 `data-theme` + token.css 机制；高亮/图表配色在组件内显式绑定主题（暗色一套显式配色，D9）。

### 10.2 关键约束

- 消息存储契约（agent_sessions/消息文本）**零改动**（B8）。
- 事件流契约（text_delta/text_end/tool_execution_*）**零改动**（B1 隐含假设 4）。
- 飞书侧（CardKit）不动；HTML 原始内容不渲染（D3）。
- 既有 E2E（assistantChat/assistantSessions/assistantConfirm 等）与既有 662+ 测试不回归。
