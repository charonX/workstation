# 访谈笔记 — 2026-08-10-pi-permission-config-ui

> 日期：2026-08-10
> 方式：对抗式需求访谈（/demand-insight），10 轮单题确认 + 方向呈现
> 输入：用户原始诉求（权限配置界面化 + 项目级配置形态讨论 + MCP 配置验证）

## 核心问题

PI agent 的权限策略目前只活在代码/JSON 文件里（全局 `agent-policy/pi-permission-config.json` + 项目级 `.pi/extensions/pi-permission-system/config.json` 手写），**UI 零呈现**——既看不到"这个项目 agent 能干什么"，也无处管理。随项目变多，逐项目手写 `.pi` 文件不可持续。

## 用户画像

- 本机单用户工作台（OPC Workstation），用户即开发者本人。
- 心智模型以**项目**为权限配置的自然维度（"项目中是不是也要加入 pi 的权限的配置"）。
- 对权限语义有基本理解（高危命令、确认卡），但不期望手写 JSON。

## 关键边界（10 轮确认）

1. **管理为主诉求**，切入 = 项目级配置 UI 化；全局出厂策略只读展示（编辑全局会推翻 ADR-020「代码规则表=唯一真源」，不做）。
2. **编辑形态 C**：可视化面板为主 + JSON 高级模式兜底。
3. **继承视图 A**：面板展示"全局基底 + 项目覆盖高亮"的完整生效形态；项目没写的规则回落全局。
4. **保存即生效 A**：保存后当前运行的会话/worker 按新规则执行（需调研 gotgenes/PI 策略热重读可行性）。
5. **全量面板化 A**：pi-permission-config.json 全字段域可视化——bash 高危规则族 / 工具级裁决 / 全局兜底 / path 白名单 / 外部目录 / authorizerChain / 其他开关（yoloMode、debugLog、doublePressToConfirm、预览长度）。
6. **入口 A**：管理区项目详情页内嵌"权限配置"区块（Settings 四 tab 不加权限 tab；REQ-AGENT-033「设置页无权限 tab」随本 story 推翻）。
7. **首次编辑时生成 A**：项目创建不预置 `.pi` 文件；UI 首次编辑才生成（模板 = 全量跟随全局初始形态）。无配置项目 = 干净继承态。
8. **面板↔JSON 单向同步 A**：面板是受控生成器（保存重新生成完整 JSON）；JSON 自由区保留面板不认识的字段（标记"自定义字段"只读展示，面板保存不冲掉）。
9. **保存校验 A（fail-closed）**：JSON 语法 + schema 校验，非法拒绝落盘并报错定位；项目文件保持上次合法状态，运行中 agent 不受影响。
10. **MCP 单独立项**：PI SDK 0.83 官方不支持 MCP（需 extension），与本 story 权限主题不耦合。

## 隐含假设

1. 全局策略的 UI 呈现 = 读**代码规则表**（BASH_RULES，ADR-020 真源）渲染人可读规则列表，而非展示部署 JSON 原文——对齐"代码=真源"语义（需 tech-design 定实现）。
2. "保存即生效"的实现路径依赖调研：gotgenes 是否支持运行时重读策略文件；若不支持，需在 worker/主进程侧做热替换链路（重部署 + 通知）。
3. 校验失败阻止保存的前提是校验器可靠（schema 校验器误报会让用户卡死）——tech-design 需给校验器来源（gotgenes schema URL 已存在于 JSON `$schema` 字段）。
4. 面板与 JSON 的文件交汇点 = `.pi` 文件本身；无独立 DB 状态（运行时真相 = 文件，gotgenes cwd 发现路径）。

## 矛盾/风险

1. **ADR-020 张力**：全局"代码=真源" vs UI"展示全局"——实现上需要规则表 → 人类可读 UI 的映射管线（规则表是 RegExp source + globs，需渲染成可读卡片），工作量在"呈现"不在"编辑"。
2. **全量面板化的表达面**：path 白名单 / external_directory 是**路径列表**形态，UI 成本高于开关；authorizerChain 是链式结构。全量面板化 = 本期 UI 组件面较大（列表编辑器、链编辑器）。
3. **保存即生效的边界**：若 gotgenes 热重读不可行，需降级方案（如 worker 重新部署 + 会话级 reload）——待调研，可能影响交付范围。
4. **REQ-AGENT-033 冲突**：既有签核断言"设置页无权限相关 tab/区"——本 story 若加设置区权限入口会碰既有测试；已选项目详情页入口（管理区），需确认是否触碰该断言面（详情页 vs Settings 页是不同 locator）。

## 候选方向

### 方向 A（确认）：项目详情页内嵌权限配置（继承视图 + 全量面板化 + JSON 兜底）
- 适用场景：项目维度管理权限，全局只读基底，保存即生效
- 主要取舍：UI 组件面大（列表/链编辑器）；依赖热重载调研结论
- 推荐度：**首选**（10 轮确认逐项收敛）

### 方向 B：Settings 加权限 tab
- 适用场景：集中管理所有项目权限
- 主要取舍：全局配置语境混入项目级，语义混淆；直接冲突 REQ-AGENT-033 断言面
- 推荐度：不推荐（被否）

### 方向 C：纯 JSON 编辑器
- 适用场景：信任 JSON、不想要面板
- 主要取舍：门槛高，与"界面零呈现"痛点不匹配
- 推荐度：不推荐（被否）

## 确认方向

最终确认的方向：**方向 A**（Outcome/User/Why now/Success/Constraint/Out of scope 详见对话呈现，用户显式 yes）

- Outcome: 项目详情页内，可视化查看并管理该项目 PI agent 权限策略——继承视图（全局基底 + 项目覆盖高亮），全量规则面板化（bash 高危族/工具级/兜底/path 白名单/外部目录/授权链/开关），保存即生效；JSON 高级模式保留自定义字段不冲突。
- User: 本机单用户（开发者本人）
- Why now: 权限机制已落地（ADR-017/020 + 授权桥确认卡），配置面仍手写 JSON，项目变多不可持续
- Success: 新增/编辑项目权限全程 UI；保存即时生效；无配置项目干净继承全局；JSON 自定义字段不被面板冲掉
- Constraint: ADR-020 不动（全局真源只读展示）；运行时真相 = `.pi` 文件（gotgenes cwd 发现路径）；校验失败不落盘
- Out of scope: MCP（单独立项）、全局策略编辑、飞书侧权限管理、gotgenes 引擎改动

确认理由：10 轮单题确认全部收敛于同一方向，无摇摆项；被否选项均因 ADR-020 约束或语义冲突，理由一致。

## 最窄的切入点

**项目详情页权限配置区块 v1**：
1. 读全局规则表（BASH_RULES + permissionPolicy 工具默认）渲染继承视图基底（只读）

4. JSON 高级模式（自定义字段保留）
