# 访谈笔记 — 2026-08-02-ui-copilot

> 访谈日期：2026-08-05。访谈方式：单题循环 + Q/GUESS。方向拍板：**方向 B 分层交付**。

## 核心问题

在应用内查执行状态、下发任务、操作配置都要手动点菜单页面——没有对话式辅助路径。飞书入口（builtin-agent，已验收）解决"人不在电脑前"；本 story 解决"人在电脑前"的主工作台形态，两个头条价值：

1. **按 session 看历史会话**——所有对话空间（项目/通用/飞书）在一个列表里可见可回看
2. **agent 绑定项目、用项目关联的不同 skill 完成不同的事**——能力按项目分化

飞书定位收窄为"消息通知 + 简单状态查询"（用户原话；**仅定位描述，既有能力不回收**）。

## 用户画像

坐在电脑前的平台用户本人（单用户桌面应用）。痛点 = 功能定位/导航成本，不是远程能力缺失。

## 关键边界

1. **复用 builtin-agent 已验收的 PI 内核与 session 持久化**（S3/S4），内核不动；`ui:copilot` 空间 key 已预留
2. **空间模型**：`ui:copilot`（通用分组）+ `ui:project:<projectId>`（项目分组，每项目独立会话列表）+ `feishu:*`（进列表，UI 内只读）
3. **工具面按空间分级**：通用 = CLI-only（S5 不变）；项目 = CLI + SKILL.md 注入 + 项目目录 FS/脚本工具（用户明确："需要读文件跑脚本等工具"）
4. **权限语义**：高危拦截确认，其余直接放行，**不做 UI 配置**；高危分类沿用前 story"删除/配置变更/取消类"并向 FS/脚本操作延伸（清单在 crystallize 细化）；实现路线优先复用 PI 扩展生态的开源权限插件（用户指出，待验证）
5. **面板形态 = Codex 桌面式**（用户供图拍板）：主导航「助手」入口 → 左栏（新对话 + 项目分组会话列表 + 通用分组）+ 主区（项目上下文 chip + 对话窗 + 引导卡片）；不贴项目详情页、不做全局悬浮窗
6. **飞书会话 UI 内只读**；UI↔飞书消息双向桥不做（用户判断"挺不容易做"，登记为远期候选）

## 隐含假设

1. **PI 扩展生态存在可用的开源权限插件**（用户记忆，未验证）——TECH-DESIGN 前 `/research` 必验；现有调研（`wayfind/builtin-agent/research/pi-toolbox.md`）仅记录"PI 无内置权限系统 + Gondolin/Docker/OpenShell 外部沙箱路线"，未覆盖社区权限扩展。若无合适插件，回退 = 平台自实现高危分类拦截钩子
2. SKILL.md 注入（prompt 级能力）对 PI agent 行为生效——生效方式待 spike/research
3. 项目详情页"关联 Skills"现有数据可直接作为项目空间能力面来源
4. 会话列表元信息（标题/时间/分组）以合理默认呈现，无需用户配置

## 矛盾/风险

1. 飞书"定位收窄"与飞书现有全量能力（下发/配置/高危确认）并存——结论：能力不回收，UI 不重复建设飞书已有交互
2. 跑脚本 = LLM 在用户机器上执行任意命令，风险高于飞书侧任何已有操作——靠"高危确认 + 权限插件"双保险
3. 前 story 移动块 M2（确认挂起队列可见性）可能由 UI 会话中心天然承接——DESIGN 阶段评估，不预设

## 候选方向

### 方向 A：全量一次做
会话中心 + 项目空间增强 + 飞书只读一个 story 全交付。
- 适用场景：各块耦合度高、拆开没意义时
- 主要取舍：体量 25+ REQ，BUILD 周期长；飞书只读与主线耦合低，混入稀释焦点
- 推荐度：不推荐

### 方向 B：分层交付（M1→M2→M3）✅ 用户拍板
- **M1 会话中心骨架**：导航「助手」入口 + Codex 式双栏 + 通用/项目分组会话列表 + 对话收发（CLI 工具面，复用内核全量能力）+ 历史回看
- **M2 项目空间增强**：SKILL.md 注入 + 项目目录 FS/脚本工具 + 高危拦截确认（PI 权限插件路线）
- **M3 飞书会话只读**：飞书空间会话进列表、只读回看
- 适用场景：每层独立可验收；M1 落地即交付初衷主干
- 主要取舍：最大技术不确定点（权限插件）排在 M2，不阻塞主干；M3 最独立最后收尾
- 推荐度：首选——与 builtin-agent 分层交付成功路径同构

### 方向 C：项目空间优先
先做 skill 差异化（M2），会话中心从简。
- 适用场景：skill 分化价值远高于对话式查询时
- 主要取舍：风险前置是好事，但会话中心被砍后 M2 无承载 UI，实际省不下成本
- 推荐度：备选

## 确认方向

**最终确认的方向：方向 B（分层交付 M1→M2→M3）**——用户显式选择，确认意图块未提修改。

确认意图：

- **Outcome**：应用内「助手」会话中心——按 session 看所有历史对话（项目/通用/飞书），项目对话里 agent 带项目 Skills 能力可读写项目文件、跑脚本，通用对话管平台级查状态/下发/配置
- **User**：坐在电脑前的平台用户本人（飞书 = 离开电脑时的通知 + 简单查询入口，定位不变、能力不回收）
- **Why now**：内核与飞书入口已验收（builtin-agent），`ui:copilot` 空间 key 已预留，UI 是唯一缺的入口
- **Success**：不看菜单能完成：查到某项目执行情况、给项目下发任务、让 agent 用项目 skill 干一件事（如读项目文件总结）；飞书聊过的会话在 UI 里能回看
- **Constraint**：复用 PI 内核与 session 持久化不动；工具面按空间分级（通用 CLI-only / 项目 CLI+skill+FS/脚本）；权限 = 高危确认其余放行、无 UI 配置；飞书会话只读、消息桥不做
- **Out of scope**：飞书↔UI 消息双向桥；权限策略 UI 配置；飞书既有能力收窄/回收；会话重命名/删除等管理增强（DESIGN 若有低成本默认再议）；`ui:copilot` 之外的 IM 新通道

确认理由：与 builtin-agent 分层交付路径同构；每层独立可签可验收；最大技术不确定点（权限插件）不阻塞主干价值。

## 最窄的切入点

**M1 会话中心骨架**：导航「助手」+ 通用空间对话收发 + 历史会话列表。一个"能聊、能回看"的最小闭环即交付初衷主干（对话式查状态/下发/配置）。
