## 1. 问题陈述

在应用内查执行状态、下发任务、操作配置都要手动点菜单页面——没有对话式辅助路径。内置 agent 内核与飞书入口已就绪，但坐在电脑前（主工作场景）反而没有对话入口；所有对话（含飞书聊过的）没有统一的历史视图，聊完即沉；项目已关联的 Skills 只能在 flow 节点里被消费，对话 agent 用不上——同一个对话框无法"绑不同项目干不同的事"。

## 2. 解决方案

应用内新增「助手」会话中心（Codex 桌面式双栏：左栏 = 新对话 + 分组会话列表，右栏 = 对话窗），复用 builtin-agent 已验收的 PI 内核、session 持久化与确认挂起队列，不动内核。分层交付：

- **M1 会话中心骨架**：**双区模型**（2026-08-06 拍板，取代路线 A 融合左导）：**会话区**（默认落地页）左导纯会话 = 新对话（通用）+ 通用/项目（行内＋）/飞书分组 + 底部 ⚙ 设置入口；**管理区** = 旧应用壳原样整体保留（左导同旧版：仪表盘/工作区/流程/执行/内容源/技能/通知/设置），顶部「← 返回对话」，经会话区 ⚙ 进入——旧页面/路由/E2E 零改动。对话收发与流式渲染 + 历史回看 + 内联高危确认卡。工具面 = 既有 CLI 全量（通用/项目空间同）。
- **M2 项目空间增强**：项目空间对话自动注入该项目关联 Skills 的 SKILL.md；新增项目目录内读文件/跑脚本工具；权限 = 高危拦截确认、其余放行、无 UI 配置（PI 权限插件路线优先）。
- **M3 飞书会话只读**：`feishu:*` 空间会话进列表，UI 内只读回看。

空间模型：`ui:copilot`（通用分组，已预留）+ `ui:project:<projectId>`（项目分组，每项目独立会话列表）+ `feishu:<chatId>`（只读）。飞书定位 = 通知 + 简单状态查询（既有能力不回收）。

## 3. 用户故事

1. 作为用户，我想从主导航打开「助手」，看到按通用/项目分组的会话列表，以便找到并回看任何历史对话。
2. 作为用户，我想在通用空间用自然语言查执行状态/下发任务/操作配置，以便坐在电脑前也不点菜单。
3. 作为用户，我想对话触发删除/配置变更等高危操作时看到内联确认卡，以便确认/拒绝不离开对话。
4. 作为用户，我想在项目空间对话时 agent 自动带上该项目关联的 Skills，以便同一个面板绑不同项目干不同的事。
5. 作为用户，我想项目空间的 agent 能读项目文件、跑脚本（高危被拦截确认、其余放行），以便 skill 真正落地执行而不是纸上谈兵。
6. 作为用户，我想在 UI 里回看飞书会话的历史消息，以便回到电脑前审计/接续上下文（只读，不从 UI 发往飞书）。
7. 作为用户，我想点「新对话」默认归属当前选中分组，以便会话归属不出错。

## 6. 用户操作流

### S1 打开会话中心（默认落地页）
1. 用户启动应用 → 默认进入**会话区**（会话中心）
2. 左栏显示：「新对话」（通用空间）+ 通用分组 + 各项目分组（行内「＋」）+ 飞书分组 + 底部 ⚙ 设置
3. 默认选中最近一次活跃的会话（无则通用分组空态 + 引导卡）
4. 点 ⚙ → 进入**管理区**：旧应用壳原样（左导八条目），顶部「← 返回对话」回到会话区

### S3 对话收发（通用/项目空间同流程）
1. 用户在输入区输入消息 → 点发送（或回车）
2. 消息出现在对话窗，agent 流式回复逐字渲染
3. 回复完成，会话出现在左栏对应分组，可切换回看

### S5 内联高危确认
1. 对话中 agent 发起高危操作（如"删除 xx flow"）→ 对话窗出现内联确认卡（操作描述 + 确认/拒绝）
2. 用户点「确认」→ 操作执行，结果以 agent 消息呈现；点「拒绝」→ 中止，agent 告知已取消
3. 用户可暂时忽略，确认卡保持在历史中，稍后仍可点（确认与执行解耦，沿用挂起队列语义）

### S6+S7 项目空间 skill 消费
1. 用户选中项目分组 →「新对话」→ 输入"帮我总结一下这个项目的 README"
2. agent 携带该项目 Skills 指引，读项目文件/跑脚本，流式给出结果
3. 涉及高危动作（如写文件）→ 走 S5 确认卡

### S9 飞书会话只读
1. 用户在左栏找到飞书会话 → 点击 → 右栏渲染历史消息（用户/agent 气泡）
2. 无输入区；顶部或空态标注"飞书会话，请到飞书继续对话"

### 6.2 操作分支与异常（complex 必填；错误响应详见第 8 节）

| 操作流 | 分支/异常 | 去向 |
|---|---|---|
| S1 打开会话中心 | 无任何会话 | 通用分组空态（仅标题 + 当前空间提示） |
| S1 | 有会话 | 恢复最近活跃会话（lastActiveAt 最大者） |
| S1 | 管理区 ↔ 会话区往返 | ⚙ 进入 /「← 返回对话」，管理区左导八条目不变 |
| S3 发送 | trim 后为空 | 发送按钮禁用（§7） |
| S3 | 超长度上限 | 提示并拒绝发送（§7） |
| S3 | 流式回复中继续发送 | 排队（内核串行队列语义沿用），无重复提交（按钮置灰至入队） |
| S3 | 流式中断（worker 重启/崩溃） | 气泡标注中断（§8） |
| S3 | agent 未配置 / 会话不可用 / 发送失败 | §8 引导态 / 空态 / 失败气泡+重试 |
| S5 高危确认 | 确认 / 拒绝 / 稍后处理 / 回调过期 | 执行并流式结果 / 中止告知 / 卡片留历史可后点 / 卡片置灰"已处理"（§8） |
| S6+S7 项目空间 | 读类操作 | 直接放行 |
| S6+S7 | 写/脚本高危 | 走 S5 确认卡 |
| S6+S7 | 目录外写/执行 | 权限层拒绝，agent 转述（§8） |
| S9 只读 | 尝试发送 | 交互不可达（无输入区），后端 403 兜底（§8） |
| F4 新对话/reset | 项目行「＋」/ 顶部新对话 / UI 会话内 /reset | 分别建 `ui:project:<pid>:<sid>` / `ui:copilot:<sid>` / 同分组新会话并切换（§7.1） |

## 7. 表单与输入验证

唯一用户直接输入 = 对话消息输入框。

| 字段 | 规则 | 失败反馈 |
|---|---|---|
| 消息文本 | trim 后非空；长度上限沿用 agentService 既有 enforceSizeLimit 限制 | 空消息发送按钮禁用；超限提示并拒绝发送 |
| 发送状态 | 流式回复进行中允许继续发送（排队语义沿用内核串行队列），不允许重复提交同一内容（双击防护：发送中按钮置灰至消息入队） | 置灰即反馈，无文案 |

### 7.1 业务规则
- 新对话归属（2026-08-06 拍板）：**顶部「新对话」= 通用空间新对话**（固定语义，仅存在于会话区）；**项目行内「+」（悬停显现）= 该项目空间新对话**——解决无会话项目无法首发的缺口；已删除项目行无「+」；飞书分组无「+」（飞书会话只能由飞书消息产生）
- **UI 空间 /reset（/clear）= 新建会话并切换**（2026-08-06 拍板）：旧会话留列表可回看可继续；飞书空间 /reset 维持世代制不变
- 默认路由 = 会话区（助手）；管理区经会话区 ⚙ 进入，**旧页面路由与本体、管理区左导均不变**，仅顶部加「← 返回对话」
- 会话标题 = 首条用户消息截断（拍板默认值）
- 飞书空间会话不提供任何输入入口（只读）
- 项目被删除后其会话保留可回看（孤儿会话），但不可发送新消息（输入区禁用并标注项目已删除）
- agent 未配置（无 provider/key）时对话窗显示引导（跳转 Settings > Agent 配置 tab），输入区禁用

## 8. 错误状态与失败响应

| 场景 | 响应 |
|---|---|
| agent 未配置/ key 失效 | 对话窗引导态（去 Settings 配置）；发送返回 E-AGENT-LLM-FAIL 时渲染为 agent 错误消息气泡（沿用既有 userMessage 语义） |
| worker 重启中 | 发送返回"agent 正在重启"错误气泡（沿用 restartingError）；流式中断时气泡标注中断 |
| 会话不存在（已被重置/损坏） | 选中后显示空态 + "会话不可用"，允许发起新对话 |
| 项目已删除（孤儿会话） | 历史可看，输入区禁用 + 标注（见 7.1） |
| 发送网络/服务失败 | 用户消息气泡标失败 + 重试按钮 |
| FS 工具越界（目录外写/执行） | 权限层拒绝，agent 收到工具错误并转述（不暴露路径细节以外的系统信息） |
| 确认回调过期/重复 | 确认卡置灰标注"已处理"（沿用确认挂起既有语义） |
| 飞书会话尝试发送 | N/A——无输入区，交互上不可达 |

## 9. 复杂度分级

**complex**。理由：跨 renderer（新页面 + 导航）/ http routes（新增会话消息端点）/ agentService + sessionStore（空间模型扩展）/ 权限层（外部依赖 PI 扩展生态）四层；9 个稳定块分 3 里程碑；含两个未验证外部假设（H1/H2）。

## 10. 实现决策

### 10.1 模块边界与解耦
- **renderer**：新增「助手」页面（新路由 + Sidebar 导航项）；组件边界 = 会话列表 / 对话窗 / 消息渲染 / 输入区 / 内联确认卡 五块；`api/agent.js` 扩展会话与消息端点调用
- **http 层**：新增会话/消息路由（列表、历史、发送、流式），遵循 ADR-001 本地 HTTP API；确认回调复用既有 `/api/agent/confirmations` 端点，不另起
- **service 层**：agentService/sessionStore 支持 `ui:*` 空间 key 注册与按空间列举会话；内核（worker/PI 适配）不动
- **权限层（M2）**：独立模块承接高危分类与拦截，PI 权限插件优先（H1），回退自实现钩子；对 agentService 工具面以包装/挂载点方式介入，不侵入内核
- **持久化**：复用 `agent_sessions` 表 + PI JSONL，不引入新存储

### 10.2 关键约束
- 双运行时并存不变（ADR-013）；UI 空间与飞书空间共用同一 agentService 实例与挂起队列
- UI 不向飞书通道发任何消息（无消息桥）
- 工具面按空间分级是硬边界：通用空间不可获得 FS/脚本工具
