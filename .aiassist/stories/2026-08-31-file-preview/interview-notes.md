# 访谈笔记 — 2026-08-31-file-preview

## 核心问题

在 workstation 里查看项目内的 Markdown / 代码文件时，只能看到原始文本，没有渲染后的预览（Markdown 渲染、代码高亮），阅读和 review 体验差。agent 协作场景下高频出现：agent 说「我改了 src/foo.js」「文档写在 docs/a.md」，用户想看渲染结果却要离开 app。

## 用户画像

workstation 用户（开发者本人），agent 协作场景：需要查看 agent 改动/产出的项目文件。

## 关键边界

1. **双入口**：聊天内本地文件路径点击可预览 + 左侧文件树（用户明确「同时需要文件树」）。
2. **预览面板复用浏览器容器心智**：右侧滑出面板，但内容层是 React 渲染，不走 WebContentsView/file://（协议白名单是已签核安全决策，不推翻）。
3. **文件类型**：Markdown（渲染视图 + 可切源码）+ 常见代码文件（语法高亮只读）；图片（png/jpg/svg 等）成本低就带；PDF/二进制不做，明确提示「不支持预览」。
4. **纯只读**：编辑/保存是另一个 story；逃生口 = 复制内容 / 在系统默认应用打开。
5. **自动刷新**：文件被外部（agent）修改时预览自动刷新（主进程 fs.watch，现无监听设施需新建，成本可接受）。
6. **安全边界**：预览硬限制在当前项目空间根内——相对路径按根解析，`..` 穿越或根外绝对路径拒绝并提示；主进程侧校验。
7. **大文件边界**：>1MB 不读不渲染，提示「文件过大」+「在系统默认应用打开」；图片不受此限。
8. **文件树范围**：当前项目空间根目录全树，懒加载展开；默认硬编码隐藏 `.git`/`node_modules`/`dist` 等噪音目录（第一版不解析 .gitignore）；绑定当前会话项目空间（与 MarkdownRenderer 图片解析同一真源：项目 ID → registry 解析目录），通用/飞书/孤儿空间无根 → 不显示树入口。

## 隐含假设

1. 预览渲染观感应与聊天内 MarkdownRenderer 一致（同一条管线 = 天然一致，复用是硬约束）。
2. 文件树是常驻导航工具（类 VSCode Explorer 左侧栏），预览是临时查看面板——两者分开而非合体。
3. 聊天内的路径识别：本地路径可被识别为可点击（识别规则是 TECH-DESIGN 要解的题）。

## 矛盾/风险

1. story 体量偏大（IPC 层 / 预览面板 / 文件树 / 聊天入口 ≈ 4 切片）——按切片内层循环推进可控。
2. fs.watch 是主进程新设施（递归监听 macOS 支持，需注意跨平台语义）。
3. 聊天路径识别的误报/漏报风险（哪些字符串算「本地文件路径」）。

## 候选方向

### 方向 A：一体交付 —— 文件树 + 预览面板 + 聊天路径入口，一个 story 完成
- 适用场景：痛点两个入口都要，树与预览联动紧密。
- 主要取舍：体量大（≈4 切片），内层循环按切片推进可控。
- 推荐度：**首选（用户已选）**

### 方向 B：拆两个 story —— 先预览（仅聊天入口），文件树后续
- 适用场景：尽快验证预览体验。
- 主要取舍：每个 story 更小；但痛点只解一半，共享设计要两次签核。
- 推荐度：备选（未选）

### 方向 C：file:// + WebContentsView
- 推翻已签核协议白名单，渲染观感与聊天不一致。
- 推荐度：不推荐（未选）

## 确认方向

最终确认的方向：**方向 A**

确认意图（用户显式 yes：「方向A吧，其他的确认」）：

- **Outcome**: 在 workstation 内直接预览项目文件——Markdown 渲染成排版文档、代码带语法高亮，入口是聊天里的路径点击和左侧文件树
- **User**: workstation 用户（agent 协作场景下查看 agent 改动/产出文件）
- **Why now**: 内置浏览器已落地，面板容器心智和边界机制现成，文件预览是自然延伸
- **Success**: 聊天中点击本地路径 → 右侧预览打开渲染视图；文件树点文件 → 同上；文件被 agent 修改后预览自动刷新；越界路径/大文件/二进制有明确提示而非崩溃
- **Constraint**: 预览硬限制在项目空间根内（主进程校验）；只读；复用 MarkdownRenderer 渲染管线
- **Out of scope**: 编辑/保存、PDF/二进制预览、.gitignore 解析、多项目切换的树、文件操作（新建/删除/重命名）、浏览器面板本身改动

确认理由：树和预览是一个心智整体，拆开任何一个都解不了「看项目文件」的痛点。

## 最窄的切入点

切片建议（BUILD 阶段参考）：① 主进程文件服务 IPC（readDir / readFile / watch，根目录约束 + 1MB 上限）→ ② 预览面板（Markdown 渲染复用 + 代码高亮 + 错误态）→ ③ 文件树边栏 → ④ 聊天路径识别与点击接线。
