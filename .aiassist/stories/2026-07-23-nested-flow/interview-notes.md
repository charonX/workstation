# 访谈笔记 — 2026-07-23-nested-flow

## 核心问题
当前 flow 引擎不支持嵌套/子流程调用，无法将通用的通道收发逻辑（如飞书接收/发送）封装为可复用流程。每个业务 flow 都必须重复配置相同的接收/发送节点，中间处理逻辑也无法独立抽象和跨 flow 组合复用。

## 用户画像
工作站流程编排用户，自己搭建自动化生产线。需要将飞书收发等通用脚手架抽出来，让业务 flow 专注处理逻辑，实现"壳 flow + 业务子 flow"的组合。

## 关键边界
1. **调用模型**：同步调用，父 flow 阻塞等子 flow 跑完拿回结果，继续执行（函数 call 语义）
2. **子 flow 双模式**：子 flow 可多入口——独立触发（feishumessage/scheduled）或被父 flow 调用（flowInput 节点），互斥启动
3. **入口选择**：callFlow 节点显式指定子 flow ID + 入口节点 ID，配合变量映射
4. **显式出口**：子 flow 用 flowOutput 节点显式声明返回给父的变量，未到出口算失败
5. **变量隔离**：子 flow 在全新空 context 起跑，只带入参映射进来的变量，只带出参映射回去的变量；内部变量绝不污染父
6. **失败语义**：子 flow 失败/未跑到出口 → 父 callFlow 节点标记失败 → 父 flow 中止；错误分支/try-catch 后续再做
7. **嵌套层数**：多层嵌套支持，硬上限 8 层；保存 flow 时静态检测循环引用（A→B→A 直接拒）
8. **版本语义**：调用最新版本，运行时动态加载子 flow 当前定义，不做版本绑定/快照
9. **删除保护**：子 flow 被删/无 flowInput 节点时，保存父 flow 报错 + 运行时报错双保险
10. **节点类型**：新增三个一等公民节点——`flowInput`（入参声明，多入口）、`flowOutput`（出参声明，多出口）、`callFlow`（调用节点）
11. **可选列表**：只有含 flowInput 节点的 flow 才出现在 callFlow 节点的下拉选项里
12. **变量声明**：只声明变量名（字符串 key），和现有 trigger outputVariables 一致，不引入类型系统
13. **执行记录**：嵌套展示——父执行详情里 callFlow 节点可展开看到子 flow 的完整执行树/日志/产物（调用栈模型），数据模型加 parentExecutionId
14. **foreach 组合**：自然支持（foreach body 里放 callFlow 即可循环调用），不特殊处理
15. **UI 跳转**：点击 callFlow 节点可直接跳到子 flow 画布

## 隐含假设
1. flowInput 节点和 trigger 节点是不同类型（trigger 由外部事件拉起，flowInput 由父节点拉起），生命周期语义不同，分开实现
2. 子 flow 可以有 0..N 个 flowInput 节点，每个代表一个可被调用的入口
3. 子 flow 可以有 0..N 个 flowOutput 节点，不同分支可走不同出口
4. 路由/广播属于上层节点能力，不是 callFlow 本身的事——这期只做"flow 变节点"这个底层抽象

## 矛盾/风险
1. **最大风险**：执行引擎当前是单层 DAG 线性执行（`currentNodeId` 单指针），要支持嵌套需要改成栈式执行模型（保存父节点位置、切到子 flow 执行、恢复父执行），改动不小
2. 执行日志数据模型要引入 parentExecutionId + 嵌套结构，现有 nodeRecords 是扁平数组
3. 静态循环检测需要构建 flow 调用图
4. 变量映射 UI（父变量 → 子入口变量、子出口变量 → 父命名空间）配置面板比较复杂

## 候选方向

### 方向 A：同步函数调用模型（选中）
- 适用场景：飞书壳 flow + 业务子 flow 组合、通用逻辑抽库复用
- 主要取舍：引擎改栈式执行（成本中等），但获得清晰的组合语义和可预测性
- 推荐度：**首选**

### 方向 B：异步消息派发模型（未选）
- 适用场景：事件驱动、长耗时后台任务
- 主要取舍：实现简单（fire-and-forget），但拿不到结果、飞书壳无法回发消息
- 推荐度：不推荐——不符合用户飞书场景（要等结果回发）

### 方向 C：模板实例化/拷贝（已有，不冲突）
- 现有 template 机制是拷贝节点进 flow，拷贝后解耦
- callFlow 是引用执行，子 flow 改了自动生效
- 两者是不同复用模型，共存

## 确认方向

最终确认的方向：**方向 A**

确认意图：

- Outcome: flow 引擎支持子流程同步调用，飞书收发等通用脚手架能封装为外层 flow 复用
- User: 工作站流程编排用户
- Why now: 每个业务 flow 重复接飞书、处理逻辑无法独立演化
- Success: 飞书壳 flow 路由到多个业务子 flow；子 flow 可独立触发；父执行详情可展开子执行树
- Constraint: 一期调最新、同步、变量隔离、显式映射、无类型系统、无错误分支
- Out of scope: 异步派发、扇出广播、错误分支/try-catch、变量类型、版本绑定

确认理由：用户逐题确认所有语义决策，最终对整体方向说 yes。

## 最窄的切入点

## 为回流埋点
如果方向错了最可能错在哪一层：
- **技术方案层**：现有单指针 DAG 执行模型改栈式可能发现比预估复杂，或子 flow 入口绕过 trigger 的实现有坑
- **需求层**：实际用起来发现"显式映射"太繁琐，用户更想要部分上下文透传；或者"调最新"导致子 flow 改动意外破坏父 flow，需要版本绑定
