# 访谈笔记 — 2026-08-24-embedded-browser

## 核心问题

agent 在 workstation 里起了 web 服务或产出页面后，用户要切到外部浏览器、手动找端口输地址才能验证效果，「对话 → 看结果」闭环被打断；agent 访问网页只有无头抓取，用户看不到它在看什么，agent 也没有可视化浏览器可用。

## 用户画像

用户本人（单人 workstation，opc 场景）。既是面板的使用者（预览/浏览），也是 agent 操作的监督者（实时看 agent 控制浏览器、审批提交类动作）。

## 关键边界

1. **面板即浏览器，浏览器即 agent 工具**：单一浏览器实例，人可交互、agent 可通过工具驱动，用户实时看到 agent 操作。
2. **触发契约反转**：不做 URL 探测自动弹出——面板提供工具集，agent 自主调用并决定是否展开面板。
3. **人机共驾规则**：不加锁，人操作永远生效（人优先）；agent 每次操作前重读快照自行适应；面板有「agent 控制中」指示 + 一键停止 agent 控制（断控制不关页面）。
4. **可见性解耦**：收起面板 ≠ 关闭浏览器，agent 继续运行，重新展开看到当前页。
5. **安全边界**：读取自由、提交需确认（沿用 agent_confirmations 风险基建；不可逆提交类——表单提交、购买/删除语义、凭据输入——需人批准）；不存支付凭据。
6. **单页面**：无标签页；地址栏 + 历史下拉切换。
7. **聊天链接**：http(s) 链接默认面板内打开，可选手动走系统浏览器；弹窗/target=_blank 拦截转为面板内导航，绝不劫持主窗口。
8. **技术选型（方向 B）**：`WebContentsView` 主进程托管 + 内置 MCP 工具；布局 bounds 同步是已知成本。

## 隐含假设

1. agent 的感知：DOM/无障碍树快照为主，截图为按需工具（`browser_screenshot`），不做持续视觉流理解。
2. 外网浏览是一等需求（可输任意 URL），但浏览器套件（书签/历史页/下载/多标签）不做。
3. Electron 43 的 WebContentsView API 稳定可用（§10 深潜验证）。
4. 现有 pi-mcp-adapter / SDK custom tool 机制能承载内置工具集（§10 验证接入点）。

## 矛盾/风险

1. **「读取自由、提交需确认」的判定难**：识别「这个点击是不是提交类」本身不可靠——风险分级规则是 §10 最难的设计点，可能要退化为站点级/动作级白名单。
2. **bounds 同步**：窗口 resize、面板收起/展开、双区切换时 WebContentsView 坐标同步容易出「视图偏移/遮挡」类 bug。
3. **scope 已扩大一次**（面板 + 受控浏览器合并）：注意切片时守住 Out of scope，防止浏览器套件需求渗进来。

## 候选方向

### 方向 A：`<webview>` 展示 + 内置 MCP 工具
- 适用场景：纯展示型预览，控制需求弱
- 主要取舍：UI 集成最简；控制链路多一跳（webContents.fromId）；webview 标签官方不推新
- 推荐度：备选

### 方向 B：`WebContentsView` 主进程托管 + 内置 MCP 工具
- 适用场景：agent 受控浏览器（本 story 核心）
- 主要取舍：控制保真最高（主进程直持 webContents，CDP 可用）；可见性天然解耦；布局 bounds 需手动同步
- 推荐度：**首选（已确认）**

### 方向 C：面板纯展示 + 独立 headless 浏览器（双实例投影）
- 推荐度：不推荐（状态同步是持续复杂度源，「用户看到 ≠ agent 操作」bug 不断）

## 确认方向

最终确认的方向：**方向 B**

确认意图（来自步骤 7 的显式 yes）：

- Outcome: 会话区右侧内置浏览器面板——用户可手动浏览任意 URL（可交互），agent 可通过工具自主导航/读取/操作同一浏览器实例，用户实时看到 agent 的操作过程
- User: 用户本人（单人 workstation）
- Why now: 验证闭环断裂 + agent 栈无可视化浏览器，受控浏览器是面板和 agent 进化的共同底座
- Success: ① 手动输 URL 可交互浏览；② agent 调工具开页面 → 面板自动展开、实时可见；③ agent 读页面内容用于回答；④ 提交类动作走确认队列
- Constraint: 读取自由、提交需确认；人操作永远优先；收起不断连；不存支付凭据
- Out of scope: 标签页、书签、历史记录页、下载管理、多账号分区、移动端模拟、持续视觉流理解

确认理由：方向 B 的控制保真与可见性解耦是「agent 受控浏览器」硬需求，bounds 同步是一次性成本。

## 最窄的切入点

浏览器面板骨架（WebContentsView 托管 + 地址栏 + 收起/展开 + bounds 同步）先立起来且手动可浏览；再接 agent 工具集（navigate/read/click/screenshot）；最后接确认队列与「agent 控制中」指示。
