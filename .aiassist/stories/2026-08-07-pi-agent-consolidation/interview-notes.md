# 访谈笔记 — 2026-08-07-pi-agent-consolidation

> 状态：**访谈完成**（2026-08-07，待用户确认进 /to-prd）
> 前置：handoff.md（议题清单 + 实证 file:line + 硬约束），本笔记记访谈裁决。

## 核心问题（handoff 已确认）

PI agent 集成三次 story 叠加（builtin-agent → multi-agent-skills → ui-copilot）边角累积：
会话只建不收 / 日志无界 / 单子进程混居 / 权限重复确认角落 / 职责交叠。
**story 基因 = 主动清理，非事故驱动**（用户③答 (d) 印证）。

## 用户画像

本机单用户工作站（用户本人）+ 飞书单聊/群聊中的绑定操作者；PI agent 同时服务
飞书空间、UI copilot、项目空间三类对话空间。flow 引擎 agent 节点是另一条独立
路径（Claude SDK，无会话无权限交互），不在本 story 范围。

## 已确认决策

### D1. ③ 进程隔离模型 → 降级为 ADR 决策记录（不建造）

- 用户答痛点轴：**(d) 从未真崩过，预防性结构洁癖**；"如果未来做了保活处理后，全部重新拉起应该也没有太大的问题"。
- 维持单进程，REQ-AGENT-005 / ADR-014 / ADR-015 不动。
- ADR 要点：①落地（idle 淘汰 + JSONL 懒恢复）后全量重启恢复代价可接受；附**重估触发条件**——真实崩溃发生 / 出现空间间隔离需求时再谈分进程。

### D2. ⑤ 整理边界 → (c)：根 A + 根 B 都收，agentService 主体不动

- **根 A（权限缝）**：双真源（`agent-policy/pi-permission-config.json` 声明 ↔ `permissionPolicy.js` 附录 A 内建/pre-gate regex）→ 单一真源化 + 配平测试。实证：BUG-001/002/005、④双确认卡、BUG-002 登记待做全长在这条缝上。
- **根 B（worker 会话生命周期）**：随①的动刀顺势把会话生命周期抽成独立模块（`worker.js` 871 行中 sessions Map 管理/恢复编排部分）。实证：三次 story 每次都改它；③重估触发条件若发生第一刀也落在这。
- **不做**：`agentService.js`（1014 行）看门狗/重启编排拆分——本次无建造项触碰、无可见未来动刀点（②只局部动 `logs[]` 与 ping 降噪）。
- 原则（用户原话）："从根本上收敛，为以后修改打基础"；同时符合③答的"没痛感不大动"。

### D3. 两路径关系澄清（事实层）

- 两套 agent 路径**零交叠**：PI 交互对话路径（worker/agentService/agentRouter）vs Claude SDK flow 节点路径（`claudeAgentAdapter.js` 154 行，`bypassPermissions`，无会话无看门狗）。
- 关系是调用链：PI agent → 工具 flow run → HTTP API → flowEngine →（provider=anthropic 时）SDK 一次性执行。
- **混乱不来自两 SDK 共存**；全部议题长在 PI 路径内部。

### D4. 术语归位（提议未否决，生效）

- "agent 三义"写入 CONTEXT.md：① PI 对话 agent（交互会话）② flow 的 agent 节点（SDK 一次性执行）③ agentRegistry 外部 agent CLI（skill 安装兼容层）。
- 只文档归位，不改文件名不动结构。

### D5. ① 参数与语义

- **TTL = 1 小时**（用户拍板）。依据：恢复透明（JSONL 懒恢复，REQ-AGENT-005 标准 3），TTL 代价仅是冷恢复频率；1h 覆盖"吃饭/开会回来接着聊"的热场景。
- **idle 定义**（提议未否决）：任何活动即活跃（prompt/流式/工具事件刷新活跃时间）；流式中/队列中会话永不淘汰。
- **LRU 上限 50**（提议未否决）：防扇出病态的安全阀，非产品手感。
- **手动新增会话 = 显式冷却信号**（用户提出，确认成立）：UI 空间手动新建会话时，被替换的旧会话立即淘汰（JSONL 保留，切回可懒恢复）；飞书侧等价物 `/reset` 现状已如此（worker.js:793）。例外沿用流式保护：旧会话流式/队列中延迟到流结束再淘汰。

### D6. 根 A 真源方向 → (b) 代码评估器为单一真源

- 用户拍板 (b)：附录 A 语义留在代码（本就是 REQ-TRACE 契约面、签核裁决 13/14/15 落点）；`agent-policy/pi-permission-config.json` 降级为**生成产物**——生成器从代码语义产出（仅 gotgenes 热路径可见族），配平测试锁死"生成 == 部署"。
- 重定向/管道**不可见族只活在代码 pre-gate 一处**，JSON 不再出现（消除"写了等于没写"的虚假安全感；④双确认家族从此只有一个家）。
- **项目级覆盖 JSON（`<projectDir>/.pi/...`）不动**——用户/项目自定义口子，不属于出厂默认双真源问题。
- ④推论：同一命令多规则命中"只出一张卡"的优先级写法落点在代码缝层，排序细节归 tech-design；用户面契约 = ADR-017 已有「同一命令同一危险只出一张卡」。

### D7. ②⑥小项 + 成功标准 + Out of scope（用户"接受"显式签核）

- **② logs 环形 1000 条**（提议未否决）：只为崩溃诊断留窗口；ping/pong 不再逐条入日志。
- **⑥ T-7/T-9 挂本 story 新 REQ**（提议未否决）：两条全链测试钉**整理后的新缝行为**，不回挂 ui-copilot 旧 REQ。
- **成功标准（逐字签核）**：
  1. 跑 24h 常规使用，worker 常驻内存不再单调涨（sessions 有界：TTL 1h + LRU 50 + 手动新增即淘汰生效）；
  2. 主进程 `logs[]` 有界（≤1000），ping/pong 不再逐条入日志；
  3. 权限规则只改一处（代码），配平测试"生成 == 部署"绿；双确认语料集 0 双卡；
  4. T-7/T-9 两条全链 E2E 绿；
  5. ③ ADR（暂不分进程 + 重估触发条件）落盘；agent 三义写入 CONTEXT.md；
  6. 全仓 618 单测 + 148 E2E 回归全绿（现有水位不退）。
- **Out of scope（逐字签核）**：
  1. 分进程任何建造（③仅 ADR）；
  2. `agentService.js` 看门狗/重启编排拆分；worker.js 除会话生命周期外的拆分（工具执行/IPC/流式转发留原处）；
  3. Claude SDK 路径（`claudeAgentAdapter.js`）任何改动；
  4. 替换 gotgenes / 换权限引擎；REQ-AGENT-005 看门狗契约语义变更；
  5. 项目级覆盖 JSON（`.pi/...`）机制改动。
- **量化结构指标（worker.js 行数等）不设**——行数是手段不是目的，抽到"职责清晰"即止（GUESS 未被纠正）。

## 隐含假设（BUILD 前需验证）

1. **JSONL 冷恢复延迟确实秒级**——REQ-AGENT-005 标准 3 证过恢复正确性，未证延迟水位 → QA 实测（成功标准 1 的附属断言）。
2. **`logs[]` 将来不需要长期历史**——ring 1000 够诊断即可（当前无消费者实证支持）。
3. **"手动新增会话"在 UI/飞书两侧都有可识别触发事件**——实现时验证事件信号存在；未来若上"切回旧会话"功能，懒恢复兜底。

## 矛盾/风险

1. **TTL 1h 对飞书异步略激进的残余风险**：隔 1-2 小时回复 → 首条冷恢复慢一拍。低害可观测，用户已知情接受。
2. **根 A (b) 的外部依赖**：gotgenes 上游 JSON schema 演进时，生成器要跟进（第三方格式仍是部署界面）。
3. **配平测试的语料集广度**："生成 == 部署"锁得住文件一致，锁不住语义一致——语料必须覆盖双确认家族（重定向 + cwd 外路径叠加等），否则④回归无牙。
4. **手动新增即淘汰的事件语义**：若 UI 侧"新增"信号与预期不同（如批量重建），可能误淘汰活跃会话——流式保护 + 懒恢复双兜底。

## 候选方向（访谈中实际出现并已裁决）

### 方向 A：③分进程建造（爆炸半径隔离）
- 适用场景：真实崩溃发生 / 空间隔离需求出现后。
- 主要取舍：隔离性 vs REQ-AGENT-005 契约变更 + 启动延迟 + 恢复编排复杂度。
- 推荐度：**不推荐（本轮）**——用户答 (d) 无事故痛感；降级为 ADR 决策记录 + 重估触发条件（D1）。

### 方向 B：⑤最小收敛（只收双真源 + 注释，不抽模块）
- 适用场景：只想止血、不为后续修改铺路。
- 主要取舍：工作量小 vs "为以后修改打基础"不成立。
- 推荐度：**不推荐**——用户明确"从根本上收敛"（D2 选了根 A + 根 B）。

### 方向 C：根 A 以 JSON 声明为真源
- 适用场景：运营上要"改配置不改代码"调出厂规则。
- 主要取舍：配置友好 vs 冷路径行为随配置漂 + 代码须精确复刻 gotgenes glob 语义 + 不可见族在 JSON 表达无效。
- 推荐度：**不推荐**——用户拍板 (b) 代码为源（D6）；项目级覆盖 JSON 保留自定义口子。

### 方向 D（确认方向）：handoff 六议题按 D1-D7 收敛形态
- ③ ADR 记录 / ⑤ 根 A 代码为源 + 根 B 随①抽模块 / ① TTL 1h + LRU 50 + 手动新增即淘汰 / ② ring 1000 + ping 降噪 / ④归 tech-design / ⑥挂本 story 新 REQ / 术语归位。
- 推荐度：**首选（已签核）**。

## 确认方向

最终确认的方向：**方向 D**（用户"接受"显式签核）

- **Outcome**：PI agent 集成的累积边角一次整体收敛——会话生命周期有界自愈、日志有界、权限缝单一真源、worker 会话模块独立，为以后修改打好地基。
- **User**：本机单用户 + 飞书绑定操作者（体验无感）；直接受益者是未来的维护者（改权限规则改一处、改会话逻辑进一个模块）。
- **Why now**：三次 story 叠加后边角已开始咬人（BUG-002 待做、④双确认卡、内存单调涨实测）；继续贴补丁会让第四次叠加更贵。
- **Success**：见 D7 六条（逐字签核）。
- **Constraint**：REQ-AGENT-005 / ADR-014 / ADR-015 / ADR-017 不动；业务测试只读；commit 标签纪律；ABI 互斥备忘（rebuild:node / rebuild:electron）。
- **Out of scope**：见 D7 五条（逐字签核）。
