## 1. 问题陈述

PI agent 集成是三次 story 叠加出来的（builtin-agent → multi-agent-skills → ui-copilot），边角在累积并开始咬人：

- **会话只建不收**：worker 的 sessions Map 无 idle 淘汰、无上限，释放仅三条路径（同 key 重建 / 出错 / `/reset`），内存随使用单调涨，长期挂着应用就得定期重启；
- **主进程日志无界泄漏**：`logs[]` 无界、无消费者，每 2s 一条 ping 心跳日志，一天 ~4.3 万条纯泄漏；
- **权限缝双真源手工镜像**：同一套出厂权限语义活在代码附录 A 与部署 JSON 两处，靠注释手工维持一致——已经产出实际伤害（BUG-002 登记的待做未清、`echo hi > ../out.txt` 类命令一令双卡）；
- **worker 职责交叠**：871 行里会话生命周期、工具执行、IPC、流式转发混在一起，三次 story 每次都改它，每次都要重新摸清边界；
- **"agent"一词三义**：PI 对话 agent / flow 的 agent 节点 / Agent Registry 外部 CLI 共用一个词，读代码与写文档每次都要重新消歧。

这不是某个具体故障，是"边角在累积"这件事本身——继续贴补丁，第四次叠加只会更贵。

## 2. 解决方案

一次整体整理与优化（consolidation），把会咬人的边角按根收敛：

- **会话生命周期有界自愈**：idle TTL 1h 淘汰 + LRU 上限 50 + 同组单活（同组活动冷却旧会话，跨组并发）+ 水合窗口规则化（重启只恢复活跃窗口），淘汰即冷却（JSONL 保留，下次说话透明懒恢复）；会话生命周期逻辑从 worker 抽成独立模块；
- **日志有界**：`logs[]` 环形 1000 条 + ping/pong 心跳不逐条入日志（心跳语义不动，只动日志）；
- **权限缝单一真源**：出厂规则语义只留代码评估器一处，部署 JSON 降级为生成产物（仅 gotgenes 热路径可见族），配平测试锁死"生成 == 部署"；重定向/管道不可见族只活在 pre-gate，一令双卡语料清零；
- **进程隔离模型拍板落档**：维持单进程，写 ADR 决策记录（含重估触发条件），不建造；
- **术语归位**："agent 三义"写入 CONTEXT.md。

## 3. 用户故事

1. 作为**维护者**，我想要改一条出厂权限规则时只改一处代码，以便不再手工镜像两侧、不再产出一令双卡。
2. 作为**维护者**，我想要会话生命周期逻辑在一个独立模块里，以便改淘汰/恢复策略时不用通读 871 行 worker。
3. 作为**本机用户**，我想要长时间使用应用内存不单调涨，以便不用定期重启应用；静默回来后接着聊天无感知。
4. 作为**维护者**，我想要主进程日志有界且无心跳噪音，以便崩溃后能看到出事前的最近现场。
5. 作为**维护者**，我想要"agent"在文档里三义清晰（PI 对话 agent / flow agent 节点 / 外部 agent CLI），以便阅读和写作时不用重新消歧。
6. 作为**维护者**，我想要"暂不分进程"这个决定有据可查（含何时该回来重谈），以便未来不疑神疑鬼重复争论。

## 6. 用户操作流（Operation Flows）

> 本 story 多数稳定块的"用户"是维护者或完全无感的终端使用者；B8/B9 是测试资产、B10/B11 是文档资产，其 happy path = 资产存在且通过验收（见第 11 节与第 13 节 N/A 说明）。

### F1 会话静默淘汰与透明恢复（B1，终端用户无感）

| 步骤 | 用户动作 | 系统响应 | 验收锚点 |
|---|---|---|---|
| 1 | 在任一对话空间（飞书/通用/项目）正常对话 | 会话常驻内存，任何活动刷新活跃时间 | 活跃会话不被淘汰 |

## 10. 实现决策（高层，不写代码）

### 10.1 模块边界与解耦

- **新增会话生命周期模块**（worker 侧抽取）：拥有 sessions Map、淘汰调度（TTL/LRU/显式信号三触发、流式豁免）、懒恢复编排；worker 委托调用。三个辅助 Map（toolContexts/sessionQueues/lastReplies）随会话一并归该模块管理，淘汰时同步清理。
- **权限生成器为仓内脚本**：输入=代码评估器的出厂语义，输出=检入的 `agent-policy/pi-permission-config.json`（仅 gotgenes 热路径可见族）；配平测试执行生成器并断言与检入产物一致。项目级覆盖 JSON（`<projectDir>/.pi/...`）机制不动。
- **agentService 仅局部改动**：`logs[]` 改环形、ping/pong 日志降噪；看门狗/重启编排不拆不动。
- **文档面**：新 ADR（暂不分进程 + 重估触发条件）落 `adr/`；CONTEXT.md 增"agent 三义"归位。

### 10.2 关键约束

- REQ-AGENT-005（看门狗心跳/崩溃重启/JSONL 恢复/restarting 语义）不动；本 story 复用其恢复语义，不新造。
- ADR-014（PI 运行时子进程）、ADR-015（心跳控制面）、ADR-017+2026-08-07 补充（唯一执行者/单一评估）为硬约束。
- B4 抽取为行为保持重构：worker 外 observable 行为不变（除 B1-B3 新语义）。
