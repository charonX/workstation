## 分维度详情

### 1. 痛点锚定 — PASS

§1 清楚陈述三类用户痛点，而非方案：

1. 新用户无本机 Claude Code 环境 → 平台所有 AI 能力不可用；
2. 有环境的用户也要手动搭 flow 才能触发一次 agent 执行；
3. 人不在电脑前时无法了解任务状态、无法下发任务。

痛点与 wayfind 原始诉求、ADR-013 背景一致，锚定成立。

### 2. 稳定块 — WARN

9 个稳定块均有 wayfind 票号背书与"为什么不再推翻"，整体扎实。三处语义需在结晶前对齐：

- **F-1（FAIL）**：§7.1 跨引用错误——"查询是否限绑定用户由 06 决议（读全量自由，待 M4 细化）"。M4 是"对话回复语言/时区"，与读权限无关。读权限是 S6 授权语义的一部分，待定项引用了错误的移动块，结晶时该待定会被丢失。
- **W-1（WARN）**：未绑定用户权限语义在 US9 / S6 / 7.1 / 6.2 四处表述不一致（详见用户故事维度）。
- **W-2（WARN）**：S6 高危分类含"取消类"，但 §12 / wayfind 08 已把取消执行能力划出范围。高危判定规则里的"取消类"当前无对应命令，需对齐（删掉"取消类"，或按实际命令面重新定义高危集合）。

### 3. 移动块 — PASS

M1–M4 均写明了"不确定什么"，且与 wayfind 待确认项一一对应：

- M1 飞书指令菜单 → wayfind 08"tech-design 验证，降级纯文本"；
- M2 确认挂起队列可见性 → wayfind 06 遗留（interview-notes 矛盾/风险 1）；
- M3 上下文压缩触发阈值 → wayfind 07 遗留；
- M4 回复语言/时区 → 默认建议"跟随系统"。

唯一的瑕疵是 §7.1 引用了错误的 M 块（F-1）。

### 4. 可测试性 — PASS

§11.1 覆盖接缝表完整：S1–S9 每个稳定块都有 seam 与测试类型，且区分了单元/集成/E2E/人工验收。关键测试设计点已识别：

- **fake LLM provider 注入**（S3/S2 seam）——PRD 明确要求 tech-design 验证 pi-ai 是否支持 provider 注入，不支持则 agent 适配层抽象。这是对话回路可测的前提，标记正确。
- 主观观感（卡片视觉效果）不设自动化测试、REFLECT 人工验收——符合流程纪律。

### 5. 范围 — PASS

§12 范围外明确：UI copilot（独立 story）、flow 节点运行时迁移（独立 story + ADR-013）、release 触发、取消执行、多通道、多用户。范围外与 wayfind map 的"Out of scope"一致。三层 milestone（§13）把"内核 + 入口"的大 story 切成可独立验收的节奏，与 interview-notes 方向 B 一致。

### 6. 用户故事 — WARN

9 个用户故事覆盖主路径（US1–8）与关键边界（US9 未绑定用户、US1 新用户）。问题在 US9 与授权块语义不一致：

- **W-1**：US9 说"作为未绑定用户，**我发消息应被拒绝**"；S6 稳定块说"**未绑定用户拒绝写**"；6.2 说"群聊中非绑定用户发言**忽略/拒绝**"；7.1 又说"查询是否限绑定用户**待定**（读全量自由）"。wayfind 06 原文是"**未绑定者拒绝写操作**"——即读（查询）应放行。四处表述对"未绑定用户能否查询"给出三个答案。结晶 S6 前必须统一为单一语义。

## FAIL 明细（建议修复）

### F-1 §7.1 移动块跨引用错误

- **位置**：`prd.md` §7.1 跨字段/业务规则 第 2 行
- **问题**："查询是否限绑定用户由 06 决议（读全量自由，**待 M4 细化**）"。M4 是"对话回复语言/时区"（§5），与读权限无关。
- **影响**：未绑定用户的读权限是一个真实未决项，被指向了错误的移动块，结晶时该待定项会静默丢失 → S6 授权契约不完整。
- **建议修复**：把读权限待定挂到一个语义正确的 M 块（新建"未绑定用户读权限"或并入 M2 确认可见性之外的独立项），并在结晶前由人拍板（推荐 follow wayfind 06：未绑定用户只拒绝写，读放行）。

### F-2 `/status <id>` 校验规则与真实 ID 格式不符

- **位置**：`prd.md` §7 表单与输入验证 `/status <id>` 行
- **问题**：校验规则写"id 必填、**为正整数格式**"。已核实实现：execution ID 由 `crypto.randomUUID()` 生成（`src/services/taskService.js:112/229`），为 UUID 格式。按正整数校验会拒绝所有合法 ID。
- **影响**：若照此结晶为 REQ，会生成错误测试契约（合法 ID 被判无效），回流成本高。
- **建议修复**：改为按 CLI 实际解析规则定（UUID 格式，或对齐 `/status` 命令在 `opc-workstation` 中的真实校验）。结晶前以实际命令行为为准。

## WARN 明细（建议处理，不阻塞结晶前提）

### W-1 未绑定用户读权限语义未统一
US9（拒绝发消息）/ S6（拒绝写）/ 6.2（忽略/拒绝）/ 7.1（读待定）给出三个答案。统一为 wayfind 06 语义（未绑定拒绝写、读放行）并同步 US9 措辞。

### W-2 S6 高危分类含范围外"取消类"
§12 取消执行能力已划出范围，"取消类"无对应命令。建议按实际命令面（删除/配置变更）重定义高危集合。

### W-3 S7 路由并存优先级未定义
现有 REQ-CHANNEL-002 是单绑定路由（消息 → 绑定 flow trigger）。PRD 说"IM 消息路由到 agent 对话与现有绑定 flow 路由并存"，但一条消息在"通道已绑定 flow"且"用户想对话"时如何分流（by agent 开关？by 内容？优先级？）未定义。这直接决定 imRouter 分支的正确性，结晶前需明确分流规则（可在 tech-design 落）。

### W-4 高危判定规则缺少命令→风险等级映射
7.1"删除/配置变更/取消类命令自动高危"需要具体命令清单才能变成可测试规则。S5 工具面是"除 release 外全量"，但哪些命令属高危类未枚举。结晶前（或 tech-design）给出映射表。

### W-5 S8 客户端版本约束前后不一致
PRD §4 S8 写"客户端 7.20+"；wayfind 04 决议写"客户端 7.20+/7.23+"。结晶前用官方文档核实精确版本，避免高估/低估兼容面。
