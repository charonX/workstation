# 访谈笔记 — 2026-08-02-builtin-agent

> 来源：wayfind `builtin-agent`（8 票全决议，ADR-013）+ 2026-08-02 需求访谈（合并 S1+S2、供应商、确认超时、分层交付）。

## 核心问题

平台现有 AI 能力依赖本机 Claude Code 环境（新用户装完应用用不了）且只能手动搭 flow 使用；人不在电脑前时无法了解平台正在进行的任务、无法下发任务。需要**飞书对话驱动的内置 agent**：零依赖内核（PI 运行时）随应用分发，飞书单聊/群聊即入口。

## 用户画像

- **新用户**：无 Claude Code 环境，装应用后配置一个 LLM API key 即可用（DeepSeek/Kimi）。
- **本人**：远程操作场景（不在电脑前时了解任务、下发任务）。

## 关键边界

1. **入口**：飞书 IM（单聊/群聊均按对话空间建 session）；UI copilot 面板 = 独立 story（`2026-08-02-ui-copilot`）。
2. **底层**：PI（ADR-013），与 flow 节点 Claude Agent SDK 双运行时并存。
3. **供应商**：DeepSeek + Kimi（pi-ai 内置支持，含国内/海外双端点；调研已确认）。配置 = Settings Agent 区，多供应商选择器，key 存系统 keychain。
4. **工具面**：除 release 外全量 CLI 命令；CLI 即控制面（保险层，后续可命令白名单/确认钩子收紧）；不给原始 FS/DB 工具。
5. **授权**：单用户绑定（飞书 open_id，settings 配置）；高危操作（删除/配置变更/取消类）卡片确认，**挂起可稍后处理**（不超时拒绝）；下发/查询直跑。
6. **session**：按对话空间分（飞书单聊/群聊各一）；SQLite 持久化 + 不超时 + 显式 /reset；对话过长滚动摘要压缩。
7. **上下文不流入执行**：执行独立，状态靠 CLI 查询获知。
8. **流式**：CardKit 卡片流式更新（唯一可行路径；客户端 7.20+，流式窗口 10 分钟）。
9. **命令**：双轨——斜杠命令确定性直通（/status /list /reset /help）+ 自然语言走 agent；飞书指令菜单呈现（需验证，降级纯文本）。
10. **身份配置**：内置基础身份固定（平台助手身份 + 工具面说明 + 授权/确认/流式汇报行为规则）；Settings > Agent 全局自定义身份（名称/语气/额外指令），所有对话空间共享（2026-08-03 访谈补；沿 REQ-FLOW-014 systemPrompt 契约模式）。

## 隐含假设

1. 新用户**已有或愿意申请** DeepSeek/Kimi API key——onboarding 摩擦点（设置区需引导文案）。
2. pi-ai 的 DeepSeek/Kimi provider 工具调用能力满足 CLI 工具面需求（两家均支持 function calling；pi-ai 只收录支持工具调用的模型——tech-design 前可 /research 二次验证细节）。
3. 飞书指令菜单（应用指令）能力存在且可配置——tech-design 验证，不支持则降级纯文本解析。
4. 群聊是合法对话空间：绑定用户在群里发言 agent 响应（单用户绑定语义下）。

## 矛盾/风险

1. **挂起确认可能堆积**：忽略的确认项没有自然过期——需要待确认项可见性（飞书可查/可撤销），设计点。
2. **CardKit 流式 10 分钟窗口 vs 长任务**：流式自动关闭后的状态呈现（降级为普通消息 + 查询命令），设计点。
3. **S1+S2 合并后 story 体积大**：靠 3 层 milestone 控制验收节奏。
4. **双运行时共存**：SDK（flow 节点）与 PI（内置 agent）两套凭证/依赖模型——已在 ADR-013 记录。

## 候选方向

### 方向 A：一次性全量
- 适用场景：能承受大 story 长周期。
- 主要取舍：一次签核一次交付，验收风险集中；迭代反馈慢。
- 推荐度：不推荐

### 方向 B：按使用回路分层交付
- 适用场景：story 跨内核 + 入口，需要分层验证。
- 主要取舍：3 个 milestone 各自可验收；早期只覆盖查询回路，下发/流式/命令后到。
- 推荐度：首选（用户确认）

### 方向 C：纯内核先行
- 适用场景：内核独立验证。
- 主要取舍：内核无入口、用户感知为零（已因合并否决）。
- 推荐度：不推荐（已否决）

## 确认方向

最终确认的方向：**方向 B（分层交付，3 milestone）** + 上述全部关键边界。

确认意图（2026-08-02 显式 yes）：

- Outcome: 用户在飞书里通过对话（自然语言 + 斜杠命令）驱动平台——了解正在进行的任务、下发任务并实时看到进度（卡片流式），高危操作确认后执行；agent 底层零本机依赖（PI + DeepSeek/Kimi + keychain 配置）
- User: 平台新用户（无 Claude Code 环境）+ 本人（远程操作）
- Why now: 应用已可分发（ADR-012），新用户装完用不了现有 agent 能力；飞书通道已就绪（ADR-007）
- Success: 飞书单聊里查执行状态 / 下发任务 / 流式卡片进度 / 高危确认闭环全部可用；单用户绑定生效；session 重启可恢复
- Constraint: 工具面 = 除 release 外全量 CLI 命令；CLI 即控制面（保险层）；CardKit 流式约束（客户端 7.20+、流式窗口 10 分钟）；单用户绑定；供应商 DeepSeek + Kimi
- Out of scope: UI copilot 面板（独立 story）；flow 节点运行时迁移（独立）；release 触发；取消执行能力；多用户/组织

确认理由：合并后 story 是"内核 + 入口"双层结构，飞书入口即内核验证 seam；分层让每个 milestone 独立验收，控制大 story 风险。

## 最窄的切入点

**Milestone 1：飞书单聊自然语言对话 → 查询回路**——用户发"看看执行情况"→ PI agent（DeepSeek/Kimi）→ CLI 查询工具 → 文本回复。跑通：内核（PI 集成 + session + 工具面）+ 飞书接收/发送 + 授权单用户绑定雏形。
