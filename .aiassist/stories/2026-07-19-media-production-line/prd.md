# 媒体生产线 · 收集管线

> 状态：结晶中
> 故事 ID：`2026-07-19-media-production-line`
> 最后更新：2026-07-19

---

## 1. 问题陈述

作为 solo 内容创作者，我内容生产的上游——**收集**——是手工、零散、攒不起来的：

- 阅读时（手机/桌面，X、公众号、网页）看到的好内容没有顺手的通道收进系统；靠收藏夹/备忘录存下的链接，之后再也没打开过。
- 想持续跟踪一个主题（如 AI 科技动态），得自己每天逐个源翻看，同样的动作天天重复。
- 收集到的东西散落各处、没有结构，写文章/做视频要用时找不到、用不上。

收集是每天都要做的动作，但每一次都从零开始，无法沉淀成一条自动运转的管线。它是「收集 → 想法 → 文章 → 视频」四段生产线的第一段：上游不立，下游无从谈起。

## 2. 解决方案

**一句话**：把收集段做成一条可触发的管线——内容源是被管理的实体，定时（cron）或飞书消息触发 agent 完成抓取/搜索/合成，产物以 markdown 落进项目素材库并同步飞书文档，结果经飞书送达。

**一段话**：系统层补齐四块地基——接通调度（cron 真正触发 flow）、headless 模式 DB 落盘、新增飞书通道（长连接收发消息）与内容源一级实体（含管理 UI）；收集能力本身（网页转 markdown、主题日报合成、飞书文档同步）以 skill 形式沉淀，经现有 skill 注入机制进入项目，由 flow 中的 agent 节点调用。飞书一身三任：触发源（发链接）、投递通道（收日报/确认）、沉淀地（云文档副本）；应用内新增通知中心承载系统事件（执行失败、通道掉线、产物产出）。

## 3. 用户故事

1. **作为创作者**，我可以把常看的信息源登记为内容源（名称/类型/配置/启停），并在应用界面里直接管理它们，让系统知道"从哪收"。
2. **作为创作者**，我可以为主题（如 AI 科技新闻）配置一条定时收集 flow（每天 10:00），到点自动产出一份科技日报 markdown 写入项目素材库，并在飞书收到日报摘要。
3. **作为创作者**，我阅读时在飞书里把链接发给机器人，链接正文被读成 markdown 存进项目素材库，机器人回复确认（含文件位置；失败含原因）。
4. **作为创作者**，日报和速存产物可以同步为飞书云文档，方便我在手机上翻阅。
5. **作为创作者**，我可以在无人值守（常驻 headless server）模式下运行上述定时流程；CLI 手动运行时即使 App 未启动也能自起服务，且执行记录与产物持久保存不丢失。
6. **作为创作者**，抓取失败（链接失效/需登录/超时）时我能在飞书收到明确失败原因，而不是静默无响应。
7. **作为创作者**，我打开应用能在通知中心看到关键系统事件（日报产出、执行失败、通道掉线），不用主动翻执行记录。
8. **作为创作者**，我可以一键从内置模板创建"定时日报"和"链接速存" flow，只需配好内容源和飞书凭据就能跑，不用从零编排。

| 9 | **收集能力 skill 化**：网页抓取转 markdown、主题日报合成、飞书文档同步等逻辑全部实现在项目 skill 层，经现有 skillService 安装注入；系统内核不含抓取代码 | 符合系统既有 skill 架构（ADR-003/004）与泊舟方法论"能力沉淀为 skill" |

| 11 | **开箱模板**：内置 2 个 flow 模板（定时日报、链接速存）+ 3 个收集 skill 包（fetch-to-markdown、topic-daily-digest、feishu-doc-sync）；UI 一键"从模板创建"，创建链接速存模板时自动完成通道绑定 | tech-design 确认：用户目标是拿来就用，模板是验收场景的最短路径 |

## 6. 用户操作流（Operation Flows）

### 6.1 主流程 / Happy Path

**OP-1 配置飞书通道**（稳定块 5）

| 步骤 | 用户动作 | 系统响应 | 验收锚点 |

| 1 | 在 Settings 填入飞书 App ID / App Secret 并保存 | 校验非空，保存凭据，建立长连接 | settings 持久化 |
| 2 | 查看通道状态 | 显示"在线"（连接中/在线/掉线三态） | CLI/API 可查状态 |

**OP-2 内容源管理（CLI + UI 双入口）**（稳定块 3）

| 步骤 | 用户动作 | 系统响应 | 验收锚点 |
|---|---|---|---|
| 1 | `opc-workstation source create` 或 UI 管理页新建，提交名称/类型/tags/配置 | 字段校验通过，入库 | API/CLI/UI 列表可见且一致（含 tag 标签） |
| 2 | UI 上编辑/停用/删除内容源 | CRUD 生效 | DB 状态正确，UI 实时刷新 |

**OP-3 定时日报**（稳定块 1、4、8）

| 步骤 | 用户动作 | 系统响应 | 验收锚点 |
|---|---|---|---|
| 1 | 建收集 flow（trigger 声明 topic 变量 → agent 节点引用内容源收集合成）并发布 | flow status=published | flows 表 |

**OP-4 飞书链接速存**（稳定块 5、6、8）

| 步骤 | 用户动作 | 系统响应 | 验收锚点 |
|---|---|---|---|

### 6.2 分支与异常

| 触发条件 | 分支结果 | 对应错误状态 |
|---|---|---|
| Schedule 到点但 flow 为 draft / 已删除 | 不创建执行；记日志并标记 schedule 异常 | E-SCHED-FLOW-INVALID |
| agent 节点重试耗尽仍失败 | 执行 error；飞书收到失败通知（场景 A）；通知中心落"执行失败" | E-AGENT-FAILED |
| 飞书收到不含链接的文本消息 | 不触发执行；回复使用提示 | E-MSG-NO-URL（非错误，提示分支） |
| 链接抓取失败（404/超时/反爬/需登录） | 不落盘产物；飞书回复明确失败原因 | E-FETCH-FAILED |
| 长连接断开 | 自动重连；重连失败通道状态置"掉线"，通知中心落"通道掉线" | E-CHANNEL-DOWN |
| 飞书文档同步失败 | 降级：仅文件落盘 + 飞书文字消息（含文件路径），执行不置 error | E-DOC-SYNC-FAILED |
| 通知写入失败 | 仅记日志，主流程不受影响 | E-NOTIFY-FAILED（非阻断） |
| DB 路径不可写 | server 启动失败并给出清晰错误 | E-DB-UNWRITABLE |
| 执行排队中收到新 IM 消息 | 正常入队，回执含排队位置 | —（正常分支） |

## 7. 表单与输入验证（Form / Input Validation）

| 输入字段 | 规则 | 错误提示 | 错误状态 |
|---|---|---|---|
| 内容源 name | 必填，1–64 字符 | "名称必填且不超过 64 字符" | E-SRC-NAME |
| 内容源 type | 枚举 `webpage` / `rss` / `x` / `wechat` | "不支持的内容源类型" | E-SRC-TYPE |
| 内容源 tags | 至少 1 个品类标签，每个 1–16 字符 | "请至少添加一个品类标签" | E-SRC-TAG |
| 内容源 config（webpage/rss） | 必填，合法 http(s) URL | "请提供合法 URL" | E-SRC-CONFIG |
| 内容源 config（x/wechat） | 必填非空（账号标识），格式宽松 | "请提供账号标识" | E-SRC-CONFIG |
| Schedule cron | 合法 5 段 cron 表达式 | "cron 表达式不合法" | E-SCHED-CRON |
| Schedule flowId | 必须指向存在且未删除的 flow | "flow 不存在" | E-SCHED-FLOW |
| 飞书 App ID / Secret | 必填非空 | "凭据不能为空" | E-CHANNEL-CRED |
| IM 消息 | 取文本中第一个 http(s) 链接；无链接走提示分支 | 回复使用提示 | E-MSG-NO-URL |

> 内容源管理 UI 表单与 CLI/API 使用同一套校验规则（前端即时提示，后端兜底拒绝）。通知中心无用户输入（系统生成）。

### 7.1 跨字段/业务规则

| 规则 | 触发时机 | 错误状态 |
|---|---|---|

## 8. 错误状态与失败响应（Error States / Failure Responses）

| 场景 | 触发条件 | 错误码/消息 | 用户可见状态 | 副作用/回滚 |
|---|---|---|---|---|
| 调度目标失效 | 到点时 flow 为 draft/已删 | E-SCHED-FLOW-INVALID | 日志 + schedule 标记异常；不创建执行 | 无副作用 |
| 日报执行失败 | agent 重试耗尽 | E-AGENT-FAILED | 执行 error；飞书失败通知 + 通知中心"执行失败" | 半成品文件不登记为产物 |
| 链接抓取失败 | 404/超时/反爬/需登录 | E-FETCH-FAILED | 飞书回复失败原因 | 不落盘、不追加索引 |
| 飞书发送失败 | token 失效/网络错误 | E-CHANNEL-SEND | 执行保留 success（文件已落盘），发送重试后记告警日志 | 不影响主产物 |
| 通道掉线 | 长连接断开且重连失败 | E-CHANNEL-DOWN | 状态"掉线" + 通知中心事件；恢复后置"在线"并落恢复事件 | 期间消息丢失（飞书侧不兜底） |
| 文档同步失败 | docx API 错误 | E-DOC-SYNC-FAILED | 降级为文字消息送达 | 文件落盘不受影响 |
| 通知写入失败 | DB 异常 | E-NOTIFY-FAILED | 仅日志，无用户可见状态 | 无 |
| DB 不可写 | 用户数据目录权限不足 | E-DB-UNWRITABLE | server 启动即报错退出 | 无 |
| 凭据错误 | App ID/Secret 无效 | E-CHANNEL-CRED | 通道状态"掉线"+ 提示检查凭据 | 无 |

## 9. 复杂度分级

| 维度 | 取值/说明 |
|---|---|
| 复杂度 | **complex** |
| 判断理由 | 新模块 ≥4（调度器、contentSourceService、飞书通道 adapter、notificationService）；前端新增 2 个界面（内容源管理、通知中心）；外部依赖 2+（飞书 OpenAPI、抓取目标站/搜索）；输入形态 2 种（cron tick、IM 消息）；跨模块 REQ 多；含文件系统副作用（按 STANDARDS 需真实 I/O 断言） |

## 10. 实现决策（高层，不写代码）

- **调度器模块**（server 侧）：随 HTTP server 启动读取 enabled schedules 注册 node-cron 任务；到点发布 eventBus `schedule:triggered`（现有 `taskService` 订阅者接管执行）；schedule CRUD 变更时同步增删 cron 任务。**只在进程运行期间有效，不补偿错过触发**。
- **headless DB**：`defaultDbPath()` 改为用户数据目录下固定文件；`:memory:` 仅测试显式传入。无人值守 = 常驻 headless server，常驻方式（launchd/手动）属部署层，不进系统内核。
- **内容源**：新表 `content_sources` + `contentSourceService` + `/api/content-sources` + CLI `source` 实体；前端新增管理页面。
- **飞书通道 adapter**：独立模块，负责长连接收发；通过 eventBus（如 `channel:message-received`）与 flow 触发解耦；凭据存 `settings.json`。
- **通知中心**：新表 `notifications` + `notificationService` + `/api/notifications`（列表/标记已读）；关键事件（执行终态、通道状态变更、产物产出）写入通知；前端侧边栏入口 + 未读徽标 + 列表页。
- **触发变量注入**：schedule / IM 触发时携带变量（topic、url、sender），经 `taskService.createTask` 扩展传参（现状仅 projectId/flowId，/tech-design 细化）。
- **收集 skills**：`fetch-to-markdown`、`topic-daily-digest`、`feishu-doc-sync` 三个初版 skill，经现有 skillService 安装注入项目。
- **产物登记**：executions 增加产物路径列表字段（或关联表——/tech-design），Executions 详情展示。

### 10.1 模块/服务边界（提前解耦）

| 模块 | 职责 | 不越界 |
|---|---|---|
| 调度器 | cron 注册/触发、发布事件 | 不感知 flow 内部结构 |
| contentSourceService | 内容源 CRUD 与校验 | 不感知 flow；不被 flowEngine 直接依赖 |
| 飞书通道 adapter | 长连接收发、消息解析、状态管理 | 不含收集/抓取逻辑；不直接调 flowEngine（事件解耦） |
| notificationService | 通知写入/查询/已读 | 不阻断业务主流程（写入失败仅日志） |
| 收集 skills | 抓取/搜索/合成/文档同步 | 不依赖系统内核内部 API（走公开 CLI/文件） |
| flowEngine / taskService | 执行 flow、记录执行与产物 | 不感知触发来源类型（统一 variables 注入） |

> 通道层与引擎事件解耦，未来企业微信/Telegram 复用同一通道接口；收集逻辑全在 skill 层，内核不含抓取代码。

## 11. 测试决策

- **主 seam = 产品 CLI**（`source` CRUD、`schedule`、`task run`、通道状态、通知列表），其次 HTTP API；**文件系统副作用用真实 I/O 断言**（STANDARDS 红线）。
- **飞书 mock seam**：通道 adapter 的长连接/发送目标可配置，测试用 fake 飞书 server 断言收到/发出的消息。
- **调度 seam**：测试用短周期 cron（或注入 tick）断言 `schedule:triggered` 有发布者且创建执行。
- **agent seam**：沿用 flowEngine 现有 executor 注入 mock 能力，收集 agent 用 mock adapter，离线可跑。
- **E2E**：两个验收场景（Electron + Playwright）：临时项目目录 + fake 飞书 + mock agent，断言产物文件真实存在、索引追加、飞书消息内容；内容源管理页与通知中心关键路径 E2E。
- **manual**：真实飞书环境冒烟一次（凭据不入库、不入测试）。

## 13. 补充说明

- **tech-design 三项对抗决策（2026-07-19）**：① 单 server + 统一 DB + App 顶替 headless；② per-project 串行执行队列 + IM 两步回复；③ 内置模板开箱即用。详见 tech-design.md。
- **砍项预案（白纸黑字留退路，由签核门裁决）**：结晶/测试阶段若判定 story 太厚，按序砍——① 飞书文档同步（稳定块 7）：降级为仅文件落盘 + 飞书文字消息；② 内容源类型收窄：仅 `webpage`/`rss` 进验收，`x`/`wechat` 移出；③ 通知中心（稳定块 10）：降级为仅 API + 最简列表（无徽标/无跳转）；④ 内容源管理 UI：降级为仅 CLI/API。砍任一项须同步更新本 PRD 稳定块与验收场景。
- **调度有效性边界（review R1 拆清）**：没有运行中的 server 进程就没有到点触发——定时触发只在 App 运行中或常驻 headless server 期间有效；错过的触发不补偿。CLI 手动运行自起 headless 与无人值守定时是两种独立语义（OP-6a / OP-6b）。
- **场景 A 内容来源锁定（review R2）**：日报以登记内容源聚合为主（验收锚定），agent 主题搜索为补充（不进验收）；此约束同时限定移动块 6 的设计方向。
- **原型验收裁决（2026-07-19，5 个边界问题）**：① 产物"打开/在文件夹中显示"按钮保留，/tech-design 明确 Electron preload 暴露面（shell.openPath 等）；② 通知跳转模式确认（产物产出→执行详情），写入稳定块 10；③ 通道"恢复"事件归入通道状态类、绿色，确认；④ 内容源与 flow 关联=tag 筛选，反查接口与删除警告取消（移动块 6 关闭）；⑤ 凭据保存即连接（移动块 7 关闭）。
- **ADR-003/004 文件已补录**（review R4）：原仅存在于 architecture.md 章节与 README 索引，2026-07-19 补建实体文件。
- **Feishu OpenAPI 前置调研**：长连接事件模型、消息收发、docx API 的接口细节建议先 `/research` 再进 `/tech-design`（workflow 支持该顺序）。
- **日报默认模板**（移动块 1 的初始值）：版块 = 头条 / 新工具 / 研究进展 / 观点，各 3–5 条，每条一句摘要 + 原文链接。
- **凭据存储**：初版 settings.json 明文 + 文件权限 600；加密存储后续 story。
- **最大风险假设**：飞书作为日常触点——若用户实际阅读场景不在飞书，场景 B 会沦为"建成了不按的门铃"。REFLECT 阶段以真实使用频率验证。
- **新术语**（提交 `/domain-model` 确认）：内容源（Content Source）、素材库（Material Library，项目内约定目录）、通道（Channel）、通知（Notification）。
- **与既有 story 的衔接**：`2026-07-16-flow-refinement` PRD 范围外 #9 预留了"webhook/触发来源建模"，本 story 以飞书通道落地其中的外部触发部分。
