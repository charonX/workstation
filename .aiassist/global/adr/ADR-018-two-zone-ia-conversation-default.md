# ADR-018: 双区信息架构——会话区默认落地 + 管理区旧壳原样保留

- **状态**: 已接受
- **日期**: 2026-08-06
- **相关 story**: 2026-08-02-ui-copilot
- **相关 REQ**: 待结晶（2026-08-02-ui-copilot S1）

## 背景

ui-copilot 把对话入口引入桌面应用。信息架构有三条候选：

- **路线 A（融合左导）**：单左导 = 会话分组 + 管理条目（仪表盘/工作区/流程/…）混排，点管理条目右栏切换。已做成原型评审，被判"有点乱"否决。
- **路线 B（全进设置）**：管理页面逐条搬入设置子区。FlowEditor/仪表盘等视觉型创作/扫视页面降级为"设置"语义，与降导航成本初衷矛盾，否决。
- **双区模型（改良 B）**：会话区（纯会话左导）为默认落地；管理区 = 旧应用壳**原样整体保留**（旧左导八条目不变），顶部加「← 返回对话」，经会话区 ⚙ 进入。

## 决策

采用**双区模型**：

1. **会话区 = 默认落地页**（新路由 `/assistant`）：左导纯会话——新对话（通用）+ 通用/项目（行内＋）/飞书分组 + 底部 ⚙。
2. **管理区 = 旧应用壳原样**：九条旧路由与页面本体、旧左导、既有 E2E **全部不变**，仅壳顶部加「← 返回对话」。
3. 两区共存于同一 React 应用，经路由切换；无悬浮窗、无管理条目混入会话左导。

## 后果

- 爆炸半径最小化：旧页面/导航/E2E 零改动（仅初始落地断言需适配，Settings 三套件有同型先例）。
- 对话优先的产品心智成立（启动即对话），同时不为难画 flow、看大盘等页面型任务。
- 通知/深链接目标页面仍在管理区路由，跳转逻辑不变。
- 代价：应用存在两种左导航形态（会话左导 vs 管理左导），用户经 ⚙/返回对话往返；后续 story 若要统一需再决策。

## 替代方案

见背景（路线 A 已原型化否决；路线 B 语义降级否决）。
